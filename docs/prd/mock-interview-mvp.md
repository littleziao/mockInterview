# PRD：AI 模拟面试系统第一版

## Problem Statement

用户需要一个私人使用的 AI 模拟面试系统，帮助自己基于 Markdown 简历和目标岗位进行接近真实招聘流程的练习。现有题库或泛泛聊天工具无法稳定地根据简历追问、记录回答、生成结构化复盘，也难以持续跟踪多次练习中的能力变化。

第一版要解决的问题是：让用户在本地 Web 应用中完成从简历输入、简历分析确认、连续对话式模拟面试，到复盘与学习建议、评分雷达图、长期趋势分析的完整闭环。

## Solution

构建一个单用户私人工具。用户在本地 Web 应用中配置自定义 AI 提供方，输入 Markdown 简历和可选目标岗位，选择面试模式和面试风格。系统先生成可编辑简历分析，用户确认后进入连续对话式模拟面试。

面试过程中，AI 以真人面试官视角一次提出一个问题，根据用户文字回答决定追问、轻量澄清、换题或结束。面试结束后，AI 切换为教练视角，生成复盘与学习建议，包括总体评价、亮点、主要问题、逐题点评、可改进表达示例、参考答案、知识点参考、下一次练习建议、学习框架、评分雷达图和长期趋势分析。

第一版采用本地 Web 应用形态：React + TypeScript + Vite 前端，Python + FastAPI 后端，本地 SQLite 数据库保存面试记录和趋势数据，自研轻量 AI Provider 层支持用户自定义模型服务，不引入 LangChain。

## User Stories

1. As a 用户, I want 配置自定义 AI 提供方, so that 我可以使用自己选择的模型服务完成模拟面试。
2. As a 用户, I want 在本地私有配置中保存 baseUrl、apiKey 和 model, so that 我的模型密钥不会进入代码仓库或云端。
3. As a 用户, I want 在设置页检查当前模型配置是否可用, so that 开始面试前能确认 AI 调用正常。
4. As a 用户, I want 输入、粘贴或导入 Markdown 简历, so that 系统能基于我的真实经历生成面试内容。
5. As a 用户, I want 可选填写目标岗位, so that 系统能按岗位方向调整问题侧重点和评价标准。
6. As a 用户, I want 不填写目标岗位时让系统根据简历推断面试方向, so that 我可以快速开始练习。
7. As a 用户, I want 选择单轮面试, so that 我可以快速完成一场完整模拟面试。
8. As a 用户, I want 选择多轮面试, so that 我可以模拟真实招聘流程中的多场面试。
9. As a 用户, I want 多轮面试默认包含同事技术面、资深技术面和主管综合面, so that 面试流程贴近真实招聘决策视角。
10. As a 用户, I want 可选加入 HR 面, so that 我可以练习求职动机、稳定性、薪资期望、入职时间和职业规划相关问题。
11. As a 用户, I want 选择学习梳理面, so that 我可以用低压力方式梳理知识点。
12. As a 用户, I want 选择压力面, so that 我可以模拟更接近真实面试压力的追问节奏。
13. As a 用户, I want 默认使用学习梳理面, so that 初次使用时不会过度受挫。
14. As a 用户, I want 系统在面试前生成简历分析, so that 我能确认 AI 是否正确理解我的背景。
15. As a 用户, I want 查看背景摘要、关键项目、技术栈、可能追问点、风险点和表达不清之处, so that 我知道系统会如何围绕简历提问。
16. As a 用户, I want 编辑简历分析, so that 我可以修正 AI 对简历的误读。
17. As a 用户, I want 标记希望重点练习的内容, so that 面试更贴合当前准备目标。
18. As a 用户, I want 标记不希望重点追问的内容, so that 系统能降低这些方向的提问优先级。
19. As a 用户, I want 系统不要把不希望重点追问的内容当成绝对禁问, so that 岗位相关风险仍能在复盘中被指出。
20. As a 用户, I want 在确认简历分析后开始面试, so that 面试建立在我认可的简历理解上。
21. As a 用户, I want 面试以连续对话方式进行, so that 体验接近真实面试而不是一次性题单。
22. As a 用户, I want 每次只看到一个问题, so that 我能专注回答当前问题。
23. As a 用户, I want 使用文字回答, so that 第一版不需要语音、录音或实时转写。
24. As a 用户, I want 每场面试默认包含 6 个主问题, so that 练习时长可控。
25. As a 用户, I want 每个主问题最多 2 次追问, so that 面试既有深度又不会无限延展。
26. As a 用户, I want AI 根据我的回答决定追问、轻量澄清或换题, so that 面试过程不是机械问答。
27. As a 用户, I want 答不上来时 AI 可以换一种问法或缩小范围, so that 我不会完全卡死。
28. As a 用户, I want 面试中不直接展示参考答案, so that 模拟面试真实感不被破坏。
29. As a 用户, I want 面试过程中 AI 只保持真人面试官视角, so that 它不会在中途变成讲课。
30. As a 用户, I want 手动结束当前面试, so that 我可以在时间不够时提前进入复盘。
31. As a 用户, I want 放弃进行中面试, so that 不需要为无效练习生成复盘。
32. As a 用户, I want 每次回答后自动保存进行中面试, so that 刷新页面或重新打开后可以继续。
33. As a 用户, I want 未完成或放弃的面试不进入长期趋势分析, so that 趋势数据只反映完整练习。
34. As a 用户, I want 面试结束后统一查看复盘与学习建议, so that 我可以集中学习和改进。
35. As a 用户, I want 查看总体评价, so that 我知道本次表现的整体水平。
36. As a 用户, I want 查看亮点, so that 我知道哪些表达或能力值得保留。
37. As a 用户, I want 查看主要问题, so that 我知道最需要改进的地方。
38. As a 用户, I want 查看每个主问题的简短点评, so that 我能按问题回看自己的表现。
39. As a 用户, I want 查看可改进表达示例, so that 我知道下一次可以怎么说得更好。
40. As a 用户, I want 查看参考答案, so that 我能学习更完整、更有条理的回答方式。
41. As a 用户, I want 参考答案不是唯一标准答案, so that 我不会误以为面试只有一种正确说法。
42. As a 用户, I want 查看知识点参考, so that 我知道需要补充哪些概念、原理或实践经验。
43. As a 用户, I want 查看学习框架, so that 我知道下一步应该按什么主题或顺序补齐能力。
44. As a 用户, I want 查看下一次练习建议, so that 我可以持续改进。
45. As a 用户, I want 查看评分雷达图, so that 我能快速看出强项和短板。
46. As a 用户, I want 能力模型包含专业知识准确性、项目经验表达、问题分析能力、技术深度、沟通结构化和岗位匹配度, so that 评分有稳定坐标。
47. As a 用户, I want 每次完整面试保存为面试记录, so that 我可以之后回看。
48. As a 用户, I want 在历史与趋势页查看本地历史, so that 我能复习过去的面试记录。
49. As a 用户, I want 查看长期趋势分析, so that 我能看到多次练习中的能力变化。
50. As a 用户, I want 按目标岗位查看或对比历史记录, so that 趋势分析更贴近求职方向。
51. As a 用户, I want 将单次复盘导出为 Markdown, so that 我可以保存到笔记软件中复习。
52. As a 用户, I want 第一版无需登录, so that 我能直接在本地使用。
53. As a 用户, I want 数据保存在本地 SQLite 数据库, so that 面试记录和趋势数据不依赖云端账号。
54. As a 用户, I want 第一版不做公网 SaaS, so that 项目复杂度聚焦在核心面试体验。
55. As a 用户, I want 后续微信小程序版本复用核心面试逻辑, so that 第二阶段可以扩展到移动端。
56. As a 开发者, I want AI 调用集中在后端 Provider 层, so that 前端和未来微信小程序不会直接持有模型 API Key。
57. As a 开发者, I want 关键 AI 输出使用结构化 JSON 并由后端校验, so that 前端不会依赖不稳定自由文本。
58. As a 开发者, I want 用假的 AI Provider 测试面试流程, so that 不依赖真实模型也能验证核心行为。
59. As a 开发者, I want SQLite Repository 层保存进行中面试、完成面试、能力评分和复盘内容, so that 历史与趋势页有稳定数据来源。
60. As a 开发者, I want 核心面试逻辑不要绑定 Web UI, so that 后续微信小程序版本可以复用。

## Implementation Decisions

- 第一版是单用户私人工具，不提供登录、注册、多用户协作、团队管理、候选人/面试官双端或公网 SaaS。
- 第一版产品形态是本地 Web 应用，第二阶段再考虑微信小程序版本。
- 前端采用 React + TypeScript + Vite。
- 后端采用 Python + FastAPI，并运行在 Python/Miniconda 环境中。
- 数据库采用本地 SQLite，保存面试记录、进行中面试、复盘内容、能力评分和长期趋势分析数据。
- AI 能力通过自研轻量 AI Provider 层封装，不引入 LangChain。
- 用户可自定义 AI 提供方，配置项至少包含 baseUrl、apiKey 和 model，可扩展温度、最大 token 等参数。
- 本地私有配置不上传云端，不提交到代码仓库。
- 前端和未来微信小程序不得直接持有模型 API Key，所有模型调用由后端代理。
- 关键 AI 输出必须使用结构化 JSON，并由后端校验。覆盖简历分析、下一题或追问决策、面试复盘、能力评分和学习框架。
- 如果 AI 输出结构不合法，后端应支持重试或返回可理解错误。
- 新建面试流程是流式向导，不拆成割裂页面；它依次包含 Markdown 简历输入、目标岗位填写、面试模式选择、简历分析确认和连续对话式模拟面试。
- 设置页负责自定义 AI 提供方和本地私有配置。
- 复盘页负责展示复盘与学习建议、参考答案、知识点参考、评分雷达图、学习框架，并支持复盘导出。
- 历史与趋势页负责查看面试记录、本地历史和长期趋势分析。
- 第一版只支持 Markdown 简历，不支持 PDF 简历或 Word 简历。
- Markdown 简历导入只接受 `.md` 和 `.markdown` 文件；其他文件类型应报错且不导入。
- Markdown 简历导入读取用户选择的本地文件文本，不把原始文件保存为附件。
- Markdown 简历导入成功后直接覆盖当前简历输入区，不弹覆盖确认，不做内容合并。
- Markdown 简历导入成功后只填入简历输入区，不自动触发简历分析。
- Markdown 简历导入成功后可以在当前页面显示最近导入的文件名；文件名只作为临时界面状态，不保存进面试记录，也不作为附件处理。
- Markdown 简历导入读取失败或文件内容为空时，不覆盖当前简历输入区，并显示明确错误。
- 第一版不设置显式 Markdown 简历文件大小限制。
- 第一版 Markdown 简历导入使用按钮或文件选择器，不支持拖拽导入。
- 第一版 Markdown 简历导入按 UTF-8 读取文件；读取失败时不做其他编码探测。
- 目标岗位为可选文本输入，不做固定岗位枚举。
- 面试开始前必须生成简历分析，并允许用户编辑后确认。
- 简历分析至少包含背景摘要、关键项目、技术栈、可能追问点、风险点、表达不清之处、希望重点练习的内容、不希望重点追问的内容。
- 不希望重点追问的内容是低优先级追问方向，不是绝对禁问列表。
- 面试模式包含单轮面试和多轮面试。
- 多轮面试默认使用默认轮次模板：同事技术面、资深技术面、主管综合面；HR 面可选。
- 第一版不做自定义轮次编辑器。
- 面试风格包含学习梳理面和压力面，默认使用学习梳理面。
- 压力面应更直接、追问更紧，但不得羞辱用户。
- 学习梳理面压力更低，但仍不在面试过程中直接给出完整答案。
- 面试过程中 AI 采用真人面试官视角；面试结束后 AI 切换为教练视角。
- 面试中不展示参考答案、知识点讲解或完整纠正。
- 用户答不上来或答偏时，AI 可以轻量澄清、缩小问题范围或换一种问法。
- 第一版只支持文字回答，不做语音回答、录音或实时转写。
- 单次面试默认 6 个主问题，每个主问题最多 2 次追问。
- 用户可以手动结束面试并生成复盘。
- 用户可以放弃进行中面试；放弃面试不生成复盘，不进入长期趋势分析。
- 每次用户回答后自动保存进行中面试，刷新或重新打开后可继续。
- 复盘与学习建议在面试结束后统一展示。
- 复盘内容包含总体评价、亮点、主要问题、逐题点评、可改进表达示例、参考答案、知识点参考、下一次练习建议、学习框架、评分雷达图、能力模型和长期趋势分析。
- 参考答案是示范性回答，不是唯一标准答案。
- 能力模型固定为六个维度：专业知识准确性、项目经验表达、问题分析能力、技术深度、沟通结构化、岗位匹配度。
- 评分雷达图基于能力模型展示单次面试表现。
- 长期趋势分析基于多次完成的面试记录展示能力变化。
- 单次面试复盘支持导出 Markdown。
- 不做完整数据库备份/恢复 UI。
- 核心面试逻辑应避免绑定 Web UI，以便第二阶段微信小程序版本复用。

## Testing Decisions

- 测试应优先覆盖外部行为，而不是实现细节、prompt 文案或 UI 内部状态。
- 最高层测试边界是面试流程服务，验证用户从新建面试到完成复盘的完整行为。
- 面试流程服务测试应覆盖 Markdown 简历输入或导入、目标岗位、简历分析生成、简历分析编辑确认、单轮面试、多轮面试、主问题、追问、手动结束、放弃面试、复盘生成、能力评分和复盘导出。
- AI Provider 层使用假的 AI Provider 测试，避免测试依赖真实模型服务。
- AI Provider 层测试应覆盖结构化 JSON 输出、结构校验失败、重试和错误返回。
- SQLite Repository 层测试应覆盖进行中面试保存、刷新后恢复、完成面试保存、放弃面试、历史记录查询、趋势数据查询和复盘 Markdown 数据读取。
- 前端 E2E 测试应覆盖设置页、新建面试流程、复盘页、历史与趋势页的主路径。
- 前端 E2E 测试应验证新建面试流程是流式向导，而不是割裂页面跳转造成状态丢失。
- 前端 E2E 测试应覆盖 Markdown 简历导入成功、非 `.md`/`.markdown` 文件拒绝导入、空文件或读取失败时不覆盖当前输入区。
- 复盘页测试应验证总体评价、逐题点评、参考答案、知识点参考、学习框架、评分雷达图数据和导出 Markdown 都能显示或生成。
- 历史与趋势页测试应验证只有完成面试进入长期趋势，放弃或未完成面试不进入趋势分析。
- 因当前仓库尚无业务代码，第一版实现需要新建测试结构；优先从面试流程服务的集成测试开始。

## Out of Scope

- 公开注册、登录、账号系统和多用户协作。
- 云同步、跨设备同步和公网 SaaS 部署。
- 微信小程序版本实现；第一版只要求核心逻辑避免绑定 Web UI。
- PDF 简历、Word 简历和复杂简历解析。
- 拖拽导入 Markdown 简历。
- 语音回答、录音、实时转写、摄像头、眼神检测或紧张度分析。
- 自定义轮次编辑器。
- 复杂题库系统或固定岗位题库。
- 面试中展示参考答案或实时教学。
- 完整数据库备份/恢复 UI。
- PDF 导出。
- LangChain、RAG、复杂 agent 编排、多模型路由或工具调用系统。
- 外部 PR triage。
